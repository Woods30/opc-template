# 选题源契约

选题从**选题池**来，不从「content 现编的热点」来。这份技能只定**契约**：来源怎么
标识、许可状态怎么记、候选条目长什么样、增量怎么算、过滤判据怎么表达。

**模板不内置任何具体站点，也不代实例判断许可状态。** 实例自己决定接哪一路源、
那路源能不能用；模板只保证接口是稳定的。

## 五个要素

### 1. 来源标识

每一路选题源有一个**来源标识**（instance-local 的名字，不是站点名）。它出现在：

- 候选条目的 `来源标识` 字段；
- 过滤判据里的「按来源排除 / 按来源优先」；
- 丢弃日志里「因为哪个来源被丢」。

来源标识是**实例自己的命名**，不要把真实站点名写进标识里。模板里的标识只能是
`<来源标识>` 这样的占位。

### 2. 许可状态

许可状态是**候选条目的一个字段**，由实例填写、由实例判断。模板只要求它存在且
取值稳定，不给它划定含义。

契约：

- 字段名固定 `许可状态`，值取实例自定义的**稳定枚举**（例如「可用 / 待确认 /
  不可用」这样的三档），枚举值由实例在自己的选题源配置里定。
- 模板**不判断**许可状态，也**不预设**任何一档的含义。
- 许可状态**不是**过滤判据里的机械条件：工具不因为许可状态丢弃条目——那是实例
  决定的事，工具只负责按判据过滤。
- 许可状态**待确认**的条目可以留在池里，由 content 在选题时按语义判断处理。

### 3. 候选条目格式

候选条目是**池中的一条素材**，不是选题。它至少带这些字段：

| 字段 | 说明 |
|---|---|
| 原文出处 | 可回原文核实的地址。**缺它不许开题。** |
| 站内条目 | 来源站内的条目地址 |
| 来源名 | 人读的来源名 |
| 来源标识 | 见上，与来源名一一对应 |
| 发布时间 | 原文的发布时间 |
| 标题 | 条目标题 |
| 分类标签 | 来源自带的分类 |
| 来源类型 | 用于机械过滤的粗分类 |
| 来源分类 | 用于标记优先级的细分类 |
| 发现时刻 | 抓取工具把它放进池子的时刻 |
| 许可状态 | 见上 |

- **缺任一必留字段即丢弃**，丢弃原因写进**丢弃日志**，不静默丢弃。
- 字段名固定不变，实例可以加自己的字段，但上面这些不能改名、不能省。
- 条目落在 `knowledge/business/选题池.md`（单一副本）。

### 4. 增量语义

增量回答的是「这一轮要抓什么，不重复抓什么」。契约：

- 增量以**来源**为单位，各来源各自记自己的游标。
- 游标的语义是「这个来源上我上次处理到哪里」，由抓取工具自己维护，
  **不写在选题池里**——池子只有候选条目与处置标记，不装抓取状态。
- 增量判据由实例的选题源配置表达（按时间水位、按站内 ID、按页码……），
  模板不规定用哪一种。
- **处置标记参与去重**：标记为「已用」或「已弃」的条目不再重复进池。
- 一轮抓取产出的新条目**追加**进池子，不改写已有条目。

### 5. 过滤判据的表达方式

过滤判据分两层，**别混**：

| 层 | 谁做 | 判据长什么样 |
|---|---|---|
| **机械过滤** | 工具 | 来源类型排除、标题词表排除、分类标签排除 |
| **语义判断** | content | 支柱匹配、时效、口径合规、与在写或已排期内容去重 |

机械过滤的判据在**实例的选题源配置**里表达，模板只定表达方式：

- 按**来源类型**排除：列一份来源类型清单，清单内的类型整条丢弃。
- 按**标题词表**排除：列一组词，标题命中任一词的条目丢弃。
- 按**分类标签**排除：列一组分类标签，命中的条目丢弃。
- 按**来源分类**做**优先级标记**：只标记，不丢弃。标记结果给 content 看，
  由 content 决定要不要选。

判据的表达方式（模板定的部分）：

- 判据是**数据**，不是代码分支——同一个过滤维度只有一处定义。
- 判据改动只改配置，不改抓取逻辑。
- 判据**不表达许可状态**：许可状态由实例判断，工具不据此丢弃。
- 判据不写死具体站点名，只写来源标识与来源类型/分类。

## 抓取怎么跑

- 抓取以**定时任务为主**：用户级 cron / launchd 直接跑抓取脚本，**不消耗 agent
  token**。定时任务本身不在模板机制内——模板没法替用户改 crontab。
- agent **平时不联网**。池子的维持不靠 agent 跑。
- 实例可以让抓取工具**按需补拉**作兜底；兜底所需的执行权由实例自己的角色配置
  放行（模板的机制文件不可被实例修改，所以放行必须走实例配置这条路）。
- 抓取工具是**实例自己的**东西，模板不提供联网实现；模板只保证池子与契约稳定。

## 与 content 的分工

- 工具做机械过滤：明显不合格的条目不占 content 的注意力。
- content 做语义判断：支柱匹配、时效、口径合规、去重。
- **池空则不写**：池子里没有可用条目时，content 回报「无可用选题」，不硬凑选题。
- 护栏（满足任一条则不许开题）：品牌口径未对齐；候选条目没有原文出处可核实；
  与在写或已排期内容重复。

判据与护栏的细节见 `opc-workflow` 技能。
