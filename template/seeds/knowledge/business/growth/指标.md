# 指标目录

> growth 维护。这是指标**定义**的唯一来源，观测值不写在这里。

## 如何添加定义

在 frontmatter 的 `metrics` 数组里追加一项：

```json
{
  "key": "<metric_key>",
  "label": "<显示名>",
  "unit": "count",
  "aggregation": "sum",
  "scope": "publication",
  "channels": ["<channel_id>"]
}
```

- `key`：稳定 ASCII key，小写字母开头，可含数字与下划线，最长 40。
- `unit`：单位。同一个 key 不得用不同 unit 重复定义。
- `aggregation`：`sum` / `average` / `latest`。
- `scope`：`publication` 表示单篇观测，`channel` 表示账号级观测。
- `channels`：该指标适用的已启用 channel。

## 观测值写在哪里

- publication 指标：`tools/opc-workflow record-metrics <publication_id> ...`，落在该
  publication package 的 `指标.md`；同一窗口（如 `48h`、`7d`）不可覆盖。
- 账号级指标：`tools/opc-workflow record-channel-snapshot ...`，落在同目录的
  `渠道快照.md`，不得归属到单个 publication。
- 拿不到数据时用 `{"available": false, "reason": "<原因>"}`；生成视图会显示「不可得」，
  与未记录的「缺失」和数值 `0` 区分。

## 复盘

结论写在这里的正文，引用具体 metric key 与观测窗口；没有来源的数字不写。
