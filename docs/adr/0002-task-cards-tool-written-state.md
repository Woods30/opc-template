# 任务卡与完成态由工具维护，收件箱退休

原先一次派工是一行自由文本，躺在 `knowledge/inbox/<角色>.md` 里，完成态
靠编排者手工 Edit 那一行的行首字符。三个后果已经实际发生过：漏写完成时间
或结果时，workflow 会把这条「半个 ✅」静默降级回未完成，任务留在待办里等
下一次执行；撤销只写在决策文档里没写回收件箱，重启后两个角色各自从旧日志
把任务捞回来执行；编排者按记忆重写的 old_string 与磁盘实际文本不符，Edit
直接失败，留下同一任务 ID 的重复行。

改为**任务卡**：派工是一张 `knowledge/tasks/<任务 ID>.md`，由
`tools/opc-workflow task` 命令族维护，完成态由工具原子写入，收件箱不再
承担派工总线职责。任务卡的正文承载长需求，完成态承载事实，两者分离。

## 后果

- 看板改为读任务卡，收件箱退出待办体系。
- 实例里既有的收件箱任务**不迁移**（owner 决定：新旧并存代价大于收益）。
- 派工文本从「一行几百字」变成「一句话 + 详情路径」，这是记忆注入能收敛
  的前提。
