# 每角色可换 CLI 与模型，模型在安装实例时定

原先四个角色全部跑同一个 CLI 与默认模型。这套系统原本用来在同一个模型
内部做角色分工，但不同任务适合不同模型——写作与开发对模型的偏好并不相同。
HC 的模板本来就允许每角色一条独立的启动命令，OPC 的安装器也已经支持逐角色
指定 CLI 与权限模式，缺的只是模型这一层。

决定：**每个角色可独立指定 CLI 与模型，模版不决定模型**。模版的角色配置里
模型字段留空表示「用该 CLI 的默认模型」；实例在安装时逐角色选定 CLI 与
模型，写进实例自己的角色配置。模版只负责机制能跑起来。

## 理由

- 模版是公开的、多实例共用的。把具体模型名写进模版，等于替所有实例做了
  这个决定；模型名也会过期（网关改名、模型下线）。
- 写作与开发用不同模型是实例的经营选择，不是通用机制。

## 后果

- 安装流程要逐角色问 CLI 与模型；模型清单由各 CLI 自己报，不在模版里硬编码。
- 角色会话的启动命令要按 CLI 分派模型参数的写法（claude 用 `--model`，
  codex 用配置覆盖），并且 codex 必须额外带 `--no-daemon`，否则它的命令
  会跑到 HC 的调度之外。
- 实例既有角色配置里没有模型字段时，按该 CLI 的默认模型运行，不破坏旧实例。
