# 安装与升级

模版与实例是两份独立的仓库：模版只装机制，实例装真实业务。这份文档讲清
`bin/opc install` / `bin/opc upgrade` 做了什么、文件归谁、以及旧实例怎么迁过来。

## 两个仓库

| | 模版 | 实例 |
|---|---|---|
| 位置 | `~/Projects/opc-template` | `~/Projects/<实例目录>`（路径由 owner 定） |
| 版本库 | 公开仓库 `Woods30/opc-template` | 本地 git，**无远端** |
| 装什么 | `template/` 下的运行载荷 | 真实业务、实例配置、机制副本 |
| 谁能写 | owner | owner + 角色（按 scope） |

模版仓库根目录的 `.opc-template-repo` 是标记。实例安装器检测到它就拒绝执行——
模版不能变成实例。

## 安装

```sh
bin/opc install <实例目录> [前缀] [--dry-run] [--no-input] [--template <路径>]
```

顺序：

1. 解析模版源（见「缓存与自动拉取」）；
2. 校验目标：目录不存在或为空；不是模版仓库；不覆盖已有实例；
3. 复制机制：`scripts/`、`tools/`、`LICENSE`；
4. 写配置：`roles.json`、`channels.json`；
5. 装起始材料：`AGENTS.md`、`agents/`、`skills/` 与业务种子，并写
   `.opc/starters.json`（每份材料的相对路径与 SHA-256 基线）；
6. 写 `.opc/instance.json`（前缀、模版来源、install 时间）与
   `.opc/mechanism.json`（每个机制文件的 SHA-256）；
7. `git init`，做第一次提交；只包含模版生成的内容；
8. 跑实例的 `scripts/opc-install.sh --no-input`：生成启动器、角色设置、
   `knowledge/` 目录与名册；
9. 安装全局 UI（布局与 mod），写注册表。

前缀默认取目录名 slug。目标目录**不要含空格**，否则 `hc` 模板的 `command`
会被拆开。

## 升级

```sh
opc upgrade [实例目录] [--dry-run] [--force-mechanism] [--force-ui] [--yes]
opc upgrade --all
```

默认升级当前目录；`--all` 遍历注册表 `~/.config/opc/instances.json`。

升级顺序：

1. 读 `.opc/instance.json` 与 `.opc/mechanism.json`；
2. **校验机制指纹**：记录里的文件被改过或被删掉 → 打印 diff，拒绝升级；
   确认放弃本地改动后加 `--force-mechanism`；
3. 覆盖机制目录与文件；清单外的新文件（如 `opc-role.sh add` 生成的角色模板）保留；
   模版已删除的机制文件同步删除；
4. 合并配置：`roles.json` 按 `name`、`channels.json` 按 `id`，只增不改，
   新条目默认 `enabled: false`；
5. 按 `.opc/starters.json` 的基线更新起始材料（见下）；
6. 重写 `.opc/mechanism.json` 的哈希；
7. 跑实例安装器；
8. 安装全局 UI（`--all` 只在最后装一次）；
9. 做一个限定 pathspec 的提交；
10. 更新注册表。

`knowledge/` 永远不动。

### 指纹代替三方合并

实例里的机制文件是模版的副本，不允许本地定制。`.opc/mechanism.json` 记录每个
文件的 SHA-256（换行统一成 LF 后计算），升级前逐个比对：

- 全部一致：整目录覆盖；
- 有不一致：列出文件并打印模版与实例的 diff，拒绝；
- 新增文件：直接写入；
- 模版删了文件：实例里对应删除。

没有基线快照、没有 `mark`、没有冲突目录。角色模板等「清单外」文件不被指纹管理，
升级时保留。

### 起始材料按基线更新

机制之外的材料装一次就归 owner：`AGENTS.md`、`agents/`、`skills/` 与业务种子。
`.opc/starters.json` 记下每份材料的相对路径与 SHA-256 基线，升级时逐个比对：

| 状态 | 升级行为 |
|---|---|
| 存在，哈希等于基线 | 用模版版本刷新，基线跟着更新 |
| 存在，哈希不同 | 视为 owner 改过：保留、告警，不覆盖 |
| 不在实例里，基线里记过 | 视为 owner 删过：不复活 |
| 不在实例里，基线里没有 | 模版新增：补入 |
| 实例里有、模版没有 | owner 自加：永不触碰 |

业务种子只补不覆盖：实例里已经有就留着，owner 删掉的不再补。

技能目录以目录为单位冻结：目录里任一已记录文件被改、或出现 owner 新增的文件，
整个技能跳过更新并告警——免得 `SKILL.md` 与脚本出现半新半旧的版本。

两种情况直接失败：根 `AGENTS.md` 缺失、启用角色的入口文件缺失。
`knowledge/` 下的业务内容永远不动。

## 全局 UI

布局与看板 mod 只安装一份，放在 `$HERDR_APP_HOME`（默认
`~/.config/herdr-app/`）：

| 来源 | 安装名 |
|---|---|
| `template/layouts/opc.json` | `layouts/opc.json` + `layouts/opc.svg` |
| `template/layouts/focus.json` | `layouts/opc-focus.json` |
| `template/layouts/grid.json` | `layouts/opc-grid.json` |
| `template/layouts/monitor.json` | `layouts/opc-monitor.json` |
| `template/mods/opc-dashboard/` | `mods/opc-dashboard/` |
| `template/mods/opc-tabs/` | `mods/opc-tabs/` |

- 名称固定，不带实例前缀，不含 `{{...}}` 占位。
- 安装前备份到 `~/.config/opc/backups/<时间戳>/`。
- 哈希记录在 `~/.config/opc/ui.json`；已记录的本地修改需要 `--force-ui`。
- 单一全局 UI 的后果：升级任意实例都会更新所有实例共用的 UI；重启
  `herdr-app` 生效。
- `opc-tabs` 每 2 秒读当前 space 的 `<folder>/.opc/instance.json`，只有
  `kind === "opc-instance"` 才显示「看板」按钮；非 OPC 目录与远端 space 隐藏。

## 缓存与自动拉取

首次 `opc install` 会把模版 clone 到 `~/.local/share/opc/template`，并把
`bin/opc` 链到 `~/.local/bin/opc`（`~/.local/bin` 不在 PATH 时打印提示）。

| 场景 | 行为 |
|---|---|
| 普通安装/升级 | 先 `fetch`，缓存快进到 `origin/main`（非快进则中止），再 `re-exec` 缓存里的 `bin/opc` |
| `OPC_TEMPLATE` 或 `--template` 指向开发副本 | 直接用工作区代码，**不自动拉取** |
| `--no-pull` | 跳过拉取，使用缓存当前内容 |
| fetch 失败（离线/远端不可达） | 告警，用缓存继续 |
| 缓存损坏或非快进 | 中止，提示删除缓存重装 |
| 刷新后继续执行 | 设置 `OPC_CACHE_READY=1` 后 `re-exec`，避免新旧代码混跑 |

远端地址解析顺序：`OPC_TEMPLATE_REMOTE` 环境变量 → 仓库根的
`.opc-template-remote` → 开发副本的 `git origin` → 公开 HTTPS 地址。

## 注册表

`~/.config/opc/instances.json`：

```json
{
  "instances": [
    {
      "path": "<实例绝对路径>",
      "prefix": "acme",
      "installedAt": "2026-11-06T12:00:00+08:00",
      "updatedAt": "2026-11-06T12:00:00+08:00",
      "template": { "path": "...", "commit": "..." }
    }
  ]
}
```

`opc ls` 列出实例；目录缺失会标出来。`opc upgrade --all` 只升级注册表里的实例。
注册表只记元数据，不感知业务内容。

## 旧实例迁移

检测到下列任一项即进入一次性迁移：

- `layouts/`、`mods/`、`seeds/`、`tools/tests/`
- `sync-policy.json`、`template.lock.json`
- `.opc/sync-*`
- `scripts/opc-sync.sh`、`scripts/opc-new.sh`
- `.claude/commands/opc-init.md`（基线与实例一致时）

流程：

1. 读 `.opc/instance.json` 取前缀与模版来源；缺失则拒绝。
2. 用 `.opc/sync-base/`（其次实例 git 首次添加该文件的提交）作为基线，
   比对机制文件；有本地改动则打印 diff 并拒绝。
3. 删除路径若有未提交改动，拒绝并列出。
4. `--dry-run` 打印全部动作：实例内删除项、机制新增/更新、配置新增、骨架、
   全局删除项、将创建的单个提交。
5. 确认（交互或 `--yes`）后：备份到 `~/.config/opc/backups/`，删除旧副本，
   复制新机制，合并配置，物化缺失骨架，写新 `.opc/*.json`。
6. 做一个限定 pathspec 的提交。
7. 清理 `$HERDR_APP_HOME/{layouts,mods}` 里所有 `<前缀>-*` 旧产物，安装全局 UI，
   跑实例安装器，写注册表。

`knowledge/` 永不触碰。

## 护栏

- 模版仓库守卫：在模版目录跑实例安装器直接退出。
- 目标目录非空、含非法前缀、已是实例：`install` 拒绝。
- 机制文件本地改过：`upgrade` 拒绝，`--force-mechanism` 才覆盖。
- 全局 UI 已记录哈希且被改过：拒绝，`--force-ui` 才覆盖。
- 旧结构与未提交改动：拒绝，先提交或 stash。
- 提交只包含本次动作的 pathspec，不带上工作区无关脏文件。
- 所有写入先落到临时文件，再原子替换，避免中途失败留下半个文件。

## 排障

| 现象 | 处理 |
|---|---|
| `opc: command not found` | `~/.local/bin` 不在 PATH；加进 PATH 或直接用 `<模版>/bin/opc` |
| `opc upgrade` 报机制文件被本地改过 | 看 diff，确认放弃本地改动后 `--force-mechanism` |
| `opc upgrade` 报缓存非快进/损坏 | 删除 `~/.local/share/opc/template` 后重试，或 `--no-pull` |
| 升级后角色行为没变 | 提示词与权限在安装器里生成；`scripts/opc-down.sh && scripts/opc-up.sh` |
| 升级后看板没更新 | 全局 UI 只有一份；重启 `herdr-app` |
| 非 OPC space 没有「看板」按钮 | 预期行为；space 的 folder 要以实例根为准 |
| 迁移后旧前缀 UI 还在 | 确认迁移提交成功；清理步骤在提交之后，失败会保留备份 |
