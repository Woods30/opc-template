# 已采纳的模版提案

这里是**从实例回流到模版的提案存档**：每份文件是一个曾经被采纳的改进，
记录它解决什么问题、怎么改的。既是模版的变更日志，也是对提案者的致谢。

- 文件名：`<YYYY-MM-DD>-<主题 slug>.md`
- 正文：脱敏后的提案原文（五节：现象 / 泛化需求 / 期望模版改动 / 影响文件 / 脱敏自检）
- 末尾追加一行：`采纳于 <版本或日期>；实例：<脱敏后的来源描述>`

## 提案从哪来

实例里任何角色都可以提：`knowledge/work/<角色>/template-proposals/<日期>-<主题>.md`。
gm 汇总进 `knowledge/decisions/`，owner 脱敏后搬到这里，并在模版仓库里实现。

## 脱敏是硬要求

提案进这个目录之前必须过三关：

1. 没有真实品牌名、产品名、账号名；
2. 没有真实频道 id（wechat / x / zhihu / rednote / douyin 之类）；
3. 没有真实数字指标（曝光量、涨粉数、转化率）。

要举例就用 `<占位>`。模版仓库的 `scripts/opc-lint.sh` 会检查这些，
私词表由 owner 提供（`--private-words`）。
